**Inconsistencies between abstract, results and conclusion**
1. **"in all cases" is falsified by the authors' own Table 2.** On ILI, horizon 24, Pyraformer* scores MSE **1.420**, lower than every LTSF-Linear variant (Linear 1.947, NLinear 1.683, DLinear 2.215). Pyraformer is a Transformer-based method. The IMP. column for that row (47.86 %) is computed against the *underlined* FEDformer value 3.228, not against Pyraformer's 1.420. Pyraformer's MAE (2.012) is worse than NLinear's 0.858, but the abstract and §1 claim is unqualified.
2. **"20 % ~ 50 %" is not the range in Table 2.** ETTh1 at horizon 96 has IMP. = **0.80 %** and at 192 = **3.57 %**. §5.2 softens this to "in most cases by 20 % ~ 50 %", but §1 states it without qualification.
3. **A naive baseline matches/beats the paper's own proposal.** Table 2, Exchange-96: Repeat* MSE 0.081 (tie with DLinear) and MAE **0.196** (best in row, bolded), and Repeat* is best on MAE at 192 (0.289) and MSE/MAE at 336 (0.305/0.396). §5.2 acknowledges this against Transformers but not that it also ties/beats LTSF-Linear.
4. **Numbers that appear more than once and disagree.** FEDformer, Traffic, T=96, L=96: Table 2 = **0.587**; Table 7 (Ori.) = **0.587**; Table 6 (embedding "All") = **0.597**. Autoformer, Traffic, T=96: Table 2 = **0.613**; Table 7 (Ori.) = **0.613**; Table 6 ("All") = **0.629**. Informer, Traffic, T=96: Table 2 = 0.719 = Table 6 "All" = 0.719 (consistent). The Table 6 baseline row for FEDformer and Autoformer is therefore not the same run as Tables 2 and 7, and the paper does not say why.
5. **Table 5 baselines do not match Table 2.** Linear, ETTh1-96: Table 5 "Ori." = 0.395 vs Table 2 = 0.375. Informer, ETTh1-96: Table 5 = 0.974 vs Table 2 = 0.865. Table 5 is "the average test MSE of five runs" but does not state its look-back window; Table 2 uses L=336 for Linear and L=96 for Transformers (Appendix B.2). The discrepancy is consistent with a different L but is **not stated in paper**.
6. **Numbers that agree on cross-check:** Table 4 Informer column reproduces Table 2's Informer MSE exactly (Exchange 0.847/1.204/1.672/2.478; ETTh1 0.865/1.008/1.107/1.181). Table 7 "Ori." reproduces Table 2's FEDformer/Autoformer Traffic column exactly.
7. **Table 8 footnote flags an artefact rather than a finding**: "236.7M parameters of Pyraformer come from its linear decoder", i.e. the 241.4M figure is not attention cost.
8. Abstract says "nine real-life datasets"; Table 1 shows seven columns because ETTh1/ETTh2 and ETTm1/ETTm2 are grouped. Nine is correct once expanded.

## 1 SNAPSHOT
- **Paper**: Zeng, A., Chen, M., Zhang, L., Xu, Q. "Are Transformers Effective for Time Series Forecasting?" arXiv:2205.13504v3, 17 Aug 2022; published AAAI 2023 (our bib entry).
- **Type**: empirical critique / negative-result benchmark paper, plus a minimal baseline (LTSF-Linear: Linear, NLinear, DLinear).
- **Claim in one line**: on nine standard long-term-time-series-forecasting (LTSF) benchmarks, one-layer linear models beat five Transformer-based LTSF models, so the temporal-modelling advantage attributed to Transformers is, on these benchmarks, not there.
- **Evidence base**: nine public datasets (Table 1), MSE/MAE, five Transformer baselines + a "Repeat" baseline, plus six ablations (Tables 3–8).
- **Code**: https://github.com/cure-lab/LTSF-Linear (abstract).

## 2 ABSTRACT
- **Claim**: self-attention is permutation-invariant, so "the nature of the permutation-invariant self-attention mechanism inevitably results in temporal information loss."
- **Claim**: "LTSF-Linear surprisingly outperforms existing sophisticated Transformer-based LTSF models in all cases, and often by a large margin."
- **Evidence in the abstract**: only the summary of Table 2. No effect sizes, no variance, no significance test.
- **[Assessment]** "In all cases" is an overstatement of the paper's own Table 2 (see scratchpad item 1). The permutation-invariance argument is asserted in the abstract and tested only indirectly in Table 5.

## 3 INTRODUCTION AND MOTIVATION
- **Motivation**: a "surge of Transformer-based solutions" for LTSF — LogTrans (NeurIPS 2019), Informer (AAAI 2021 best paper), Autoformer (NeurIPS 2021), Pyraformer (ICLR 2022 Oral), Triformer (IJCAI 2022), FEDformer (ICML 2022) — whose gains the authors doubt (§1 p.1).
- **Key methodological complaint (§1 p.2)**: "in their experiments, all the compared (non-Transformer) baselines perform autoregressive or iterated multi-step (IMS) forecasting … which are known to suffer from significant error accumulation effects." The fix is to compare against a *direct multi-step* (DMS) baseline.
- **Stated contributions (§1 p.2)**: (i) first work to challenge Transformer effectiveness for LTSF; (ii) LTSF-Linear as a new baseline on nine benchmarks; (iii) ablations on long inputs, order sensitivity, positional/sub-series embeddings, efficiency.
- **[Assessment]** The IMS-vs-DMS point is the strongest part of the motivation: it identifies a concrete confound in the prior comparisons rather than only a conceptual objection.

## 4 LITERATURE REVIEW / RELATED WORK
- §3 (p.2–3) is a taxonomy of Transformer LTSF designs across four stages — preprocessing (seasonal-trend decomposition, normalisation), embedding (fixed positional, channel projection, local/global timestamp), self-attention scheme (LogSparse, ProbSparse+distilling, pyramidal, auto-correlation, frequency-enhanced), decoder (IMS vs DMS) — summarised in Fig. 1.
- Non-Transformer work is deferred to Appendix A "due to page limit" (§3 footnote 1). Appendix A covers ARIMA, exponential smoothing, structural models, **gradient boosting regression trees (GBRT)**, RNNs and CNNs.
- On GBRT specifically (Appendix A, p.9): "many machine learning techniques such as gradient boosting regression tree (GBRT) [10,11] gain popularity, which learns the temporal dynamics of time series in a data-driven manner. However, these methods still require manual feature engineering and model designs."
- **[Assessment]** GBRT is mentioned but **never benchmarked**. There is no tree-ensemble row in any table. Anyone citing this paper for "trees beat Transformers" would be citing something the paper does not test.

## 5 METHODOLOGY
- **Problem setup (§2)**: given C variates and look-back L, predict T future steps. IMS vs DMS defined; "IMS forecasting is preferable when there is a highly-accurate single-step forecaster, and T is relatively small. In contrast, DMS forecasting generates more accurate predictions when it is hard to obtain an unbiased single-step forecasting model, or T is large."
- **Model (§4)**: `X̂ᵢ = W Xᵢ`, W ∈ ℝ^{T×L}, one linear layer along the temporal axis, weights shared across variates, **no** spatial/cross-variate correlation modelled. Parameters: TL (Linear, NLinear), 2TL (DLinear) (Appendix B.2).
  - **DLinear** = Autoformer/FEDformer moving-average decomposition (kernel size 25, Appendix B.2) + two linear layers, summed.
  - **NLinear** = subtract the last value of the input sequence, apply linear layer, add it back — "a simple normalization for the input sequence", motivated by train/test distribution shift (Appendix D.1, Fig. 5).
- **Datasets (Table 1, Appendix B.1)**: ETTh1/h2/m1/m2 (7 variates), Traffic (862), Electricity (321), Exchange-Rate (8), Weather (21), ILI (7); 966 to 69,680 timesteps; granularity 1 week to 5 min. All public, URLs given in Appendix footnotes 2–7.
- **Metrics**: MSE and MAE only (§5.1). No MASE/sMAPE, no interval or probabilistic scores.
- **Baseline sourcing**: Table 2 footnote — "Linear* are implemented by us; Other results are from FEDformer [31]", i.e. Transformer numbers are **copied from a prior paper**, not re-run by the authors (except Pyraformer*, marked with *).
- **Look-back protocol (Appendix B.2)**: "we report L=336 for LTSF-Linear and L=96 for Transformers by default" — the two families are tuned on *different* input lengths, justified by "LTSF-Linear will be underfitting when the input length is short, and LTSF-Transformers tend to overfit on a long lookback window size."
- **Hyper-parameters**: Transformer defaults taken from the original repos; LTSF-Linear hyper-parameters "please refer to our code" (Appendix B.2) — **not stated in paper**.
- **Hardware**: NVIDIA Titan XP (§5.3, Table 8 discussion).
- **[Assessment]** Two design choices carry most of the risk: (a) Transformer numbers imported from FEDformer rather than re-run, so any tuning asymmetry in that source propagates; (b) different look-back windows for the two families. The authors argue (b) is a best-vs-best comparison, which is defensible, but it means Table 2 is not a controlled comparison at fixed L. Figure 6 (Appendix) partly compensates by sweeping L for both families.

## 6 RESULTS
- **Main comparison (Table 2, §5.2)**: LTSF-Linear is best on MSE in most of the 36 dataset×horizon cells. IMP. (best linear vs best Transformer) ranges from **0.80 %** (ETTh1-96) to **47.86 %** (ILI-24).
  - Authors' summary: "the performance of LTSF-Linear surpasses the SOTA FEDformer in most cases by 20 % ~ 50 % improvements on the multivariate forecasting, where LTSF-Linear even does not model correlations among variates."
  - Authors note the one competitive Transformer: "FEDformer achieves competitive forecasting accuracy on ETTh1. This because FEDformer employs classical time series analysis techniques such as frequency processing, which brings in time series inductive bias."
  - Naive **Repeat** beats all Transformers on Exchange-Rate "(around 45 %)", attributed to Transformers mis-predicting trend / overfitting sudden-change noise (Fig. 3(b)).
- **Look-back window (Fig. 4, Fig. 6)**: "existing Transformer-based models' performance deteriorates or stays stable when the look-back window size increases. In contrast, the performances of all LTSF-Linear are significantly boosted with the increase of look-back window size" (§5.3 p.5).
- **What the Transformers use (Table 3)**: swapping the input window from adjacent ("Close") to distant ("Far") while forecasting the same future 720 steps changes FEDformer Electricity MSE only 0.251 → 0.265 and Traffic 0.631 → 0.645; Autoformer Traffic 0.677 → 0.675 (*worse* with the closer window). Authors: "the performance of the SOTA Transformers drops slightly, indicating these models only capture similar temporal information from the adjacent time series sequence."
- **Is self-attention needed (Table 4)**: Informer → Att.-Linear → Embed+Linear → Linear monotonically improves on 7 of 8 rows (exception: Exchange-96, Informer 0.847 < Att.-Linear 1.003). Final Linear beats Informer by 3–10× on Exchange.
- **Temporal-order sensitivity (Table 5)**: shuffling the input changes Transformer MSE by ≈0 % on Exchange (FEDformer −0.09 %, Autoformer +0.09 %, Informer −0.12 %) while Linear degrades **27.26 %**; on ETTh1 the drops are Linear 81.06 %, FEDformer 73.28 %, Autoformer 56.91 %, Informer 1.98 %. Authors: "the existing Transformers do not preserve temporal order well."
- **Embeddings (Table 6)**: removing positional embeddings hurts Informer badly (Traffic-96: 0.719 → 1.035); FEDformer is barely affected or slightly improved (0.597 → 0.587).
- **Training-set size (Table 7)**: training FEDformer/Autoformer on 1 year of Traffic instead of the full 70 % split **lowers** MSE in 7 of 8 cells. Authors: "the training data scale is not the limiting reason for the performances of Autoformer and FEDformer."
- **Efficiency (Table 8)**: DLinear 0.04 G MACs / 139.7 K params / 0.4 ms / 687 MiB vs Informer 3.93 G / 14.39 M / 49.3 ms / 3869 MiB, Autoformer 164.1 ms, FEDformer 40.5 ms. Vanilla Transformer (DMS decoder) is faster than Informer (26.8 ms vs 49.3 ms) though it has more MACs than Pyraformer.
- **Univariate (Table 9, Appendix C.1)**: same conclusion; "NLinear can consistently outperform all transformer-based methods by a large margin in most time" — note "in most time", weaker than the abstract's "all cases". On ETTh1-96 Linear MSE 0.189 is worse than FEDformer-f 0.079 and Autoformer 0.071; NLinear 0.053 is best.
- **[Assessment]** The ablations (Tables 3–8) are the paper's real contribution and they are mutually reinforcing: the Transformers are insensitive to which window they get (Table 3), insensitive to shuffling that window (Table 5), and not helped by more data (Table 7). Table 5 is the cleanest single piece of evidence for the permutation-invariance argument. The headline Table-2 comparison is the weakest part, because the baselines are imported and the look-backs differ.

## 8 DISCUSSION
- The paper's own reading (§6): "our contributions do not come from proposing a linear model but rather from throwing out an important question, showing surprising comparisons, and demonstrating why LTSF-Transformers are not as effective as claimed in these works through various perspectives."
- Scope is explicitly bounded to *existing benchmarks*: "at least for the existing LTSF benchmarks" appears three times (§1, §5.3, §6).
- The paper offers a mechanism, not just a result: long-horizon forecasting on these datasets reduces to capturing trend and periodicity (Table 3, Fig. 7), which a T×L weight matrix can express directly, while a permutation-invariant attention stack cannot exploit order (Table 5).
- **[Assessment]** The claim that survives scrutiny is the narrow one: *on these nine benchmarks, with these metrics, at these horizons, the published Transformer results are not better than a one-layer linear DMS model, and the published Transformers do not use temporal order.* The broad reading — "Transformers don't work for time series" — is not what the evidence supports and is not what the authors write in §6.

## 9 LIMITATIONS
**Stated by the authors (§6 Future work):**
- "LTSF-Linear has a limited model capacity, and it merely serves a simple yet competitive baseline"; "the one-layer linear network is hard to capture the temporal dynamics caused by change points".
- Table 7 discussion: "we cannot conclude that we should use less data for training".
- §5.3: efficiency conclusions hold "at least for existing benchmarks".

**Not stated by the authors [Assessment]:**
- No significance testing or confidence intervals anywhere except the wording "average of five runs" in Tables 5 and 8; Table 2 reports single point estimates.
- Transformer numbers in Table 2 are imported from FEDformer, not re-run under the authors' protocol.
- Look-back window differs between families (L=336 vs L=96) in the headline table.
- Only MSE/MAE; no scale-free or probabilistic metric, so results are not directly comparable to the forecasting-competition literature (e.g. M5's WRMSSE).
- No tree-ensemble baseline (GBRT is discussed in Appendix A but never run).
- No intermittent-demand or count data; all nine datasets are continuous, mostly high-frequency sensor/energy/traffic series.
- The conclusion is about the *published* implementations of five specific models on *these* benchmarks; it is an audit of a benchmark suite, not a proof about architectures.

## 10 CONCLUSION AND FUTURE WORK
- Conclusion (§6): "This work questions the effectiveness of emerging favored Transformer-based solutions for the long-term time series forecasting problem… demonstrating why LTSF-Transformers are not as effective as claimed in these works."
- Future work (§6): new model designs, data processing and **benchmarks** for LTSF; and (abstract, §1) "revisiting the validity of Transformer-based solutions for other time series analysis tasks (e.g., anomaly detection)".
- **[Assessment]** The conclusion is stated more carefully than the abstract. The "benchmarks" item is, in hindsight, the paper's most consequential suggestion — it is a direct invitation to the response literature (including PatchTST, reviewed separately).

## 12 CRITICAL EVALUATION

**Strengths (max 3)**
1. **The ablations, not the headline, carry the paper.** Tables 3, 5 and 7 independently show the same thing — the Transformers are insensitive to *which* window they get, to *shuffling* that window, and to *more* training data. Three mechanisms converge on one conclusion; that is much harder to explain away than a single benchmark table.
2. **It names a concrete confound in the prior literature** (IMS baselines vs DMS Transformers, §1 p.2) and then removes it, rather than only asserting that the field is over-claiming.
3. **Cheap, checkable, and fully released.** A T×L weight matrix on public data with released code is the kind of baseline anyone can re-run, which is why the result propagated.

**Weaknesses (max 3)**
1. **The headline claim is stated more strongly than the authors' own Table 2 supports.** "In all cases" fails at ILI-24 (Pyraformer* MSE 1.420 < NLinear 1.683), and "20 % ~ 50 %" is contradicted by IMP. = 0.80 % and 3.57 % on ETTh1. §5.2 and Appendix C.1 quietly hedge to "in most cases" / "in most time"; the abstract does not.
2. **No uncertainty quantification on the main comparison.** Table 2 is single point estimates with imported baselines, and the two families are evaluated at different look-back windows (L=336 vs L=96, Appendix B.2). Several IMP. values (0.80 %, 3.57 %, 6.54 %) are small enough that a seed-variance band could cover them, and the paper provides no way to check.
3. **Internal numeric disagreements go unexplained.** The same FEDformer/Autoformer Traffic-96 configuration appears as 0.587/0.613 in Tables 2 and 7 but 0.597/0.629 in Table 6; Table 5's "Ori." baselines do not match Table 2 either. These are small, but they are exactly the consistency checks the paper demands of others.

**Credibility: HIGH** — released code on public benchmarks, a mechanistic explanation corroborated by three independent ablations, and a scope the authors themselves bound to "existing LTSF benchmarks"; the deductions are over-claiming in the abstract and no variance reporting, not unsound evidence.

**Detail on the one substantive use (`OVERVIEW.md:128`)**

The sentence bundles two propositions under Zeng. Splitting them:

- *"plain linear models rival Transformers"* on time series — **Supported.** Abstract; Table 2 (p.5); Table 4 (p.6) shows Informer improves monotonically as it is simplified to a linear layer.
- *"…because ~15k correlated windows is small-tabular territory"* — **Not supported by Zeng.** The paper does not attribute the result to small data. It tests that hypothesis directly and rejects it: Table 7 (p.8) shows FEDformer and Autoformer get *lower* error on 1 year of Traffic than on the full 70 % split, and §5.3 concludes "the training data scale is not the limiting reason for the performances of Autoformer and FEDformer." Zeng's datasets are also not small in our sense — 966 to 69,680 timesteps, up to 862 variates (Table 1). Zeng's explanation is different: long horizons need only trend and periodicity (Table 3, Fig. 7), and attention is permutation-invariant (Table 5). If we want the small-data argument, Grinsztajn 2022 (`papers/05`) and TSLANet carry it, not Zeng.
- **Domain gap to flag if a reviewer presses.** Zeng studies *multivariate long-horizon regression* on continuous sensor/energy/financial series, scored by MSE/MAE. Our task is *binary stockout-risk classification* from 30 engineered tabular features, scored by AUROC/PR-AUC. Zeng never runs a tree ensemble (GBRT appears only in Appendix A prose) and never runs a classification task. The paper supports "Transformers are not automatically the right answer for sequence prediction"; it does **not** support "Transformers lose to LightGBM on binary tabular classification". Our own `epoch_study.json` benchmark is what supports that, and it should be the cited evidence.

**Methodology we could reuse**
1. **The Table 3 "Close vs Far" probe.** Swap the model's input window for a distant one and see whether error moves. If our LightGBM's risk estimate barely changes when the four weeks of history are replaced with four unrelated weeks, that tells us the current state is doing the work — which is exactly the claim made in `OVERVIEW.md:126` ("logistic regression on net inventory position alone scores AUROC 0.859"). This would turn an assertion into a measurement.
2. **The Table 5 shuffle test.** Shuffle the temporal ordering inside the 4-week history block and re-score. A model that loses nothing was never using order. This is a cheap, defensible way to justify a tabular model over a sequence model in the AHFE paper, and it is a *published* protocol we can cite rather than invent.
3. **The Table 4 "gradual simplification" ladder.** Strip a complex model toward a trivial one and report every rung. Applied to our feature set (30 inputs → net position only) this is the strongest form of the "the task, not the learner, sets the ceiling" sentence already in `build_paper.js:199`.
4. **Table 8's honesty about practical cost.** Reporting MACs, parameters, wall-clock inference and memory in one table is a good model for defending a live in-experiment model that must return a risk estimate within a participant's turn.

**Caution for our own claim discipline**
This paper is a case study in the failure mode our `RESULTS.md` already warns about ("transformer architectures performed equivalently within bootstrap error… **Not:** 'PatchTST lost.'"). Zeng's abstract says "in all cases" and its own Table 2 has a counterexample. If we cite Zeng as a licence for strong negative claims about Transformers, a reviewer who opens Table 2 can use it against us. Cite it for the *mechanism* (permutation invariance, order insensitivity) and for the *protocol* (shuffle/Close-Far probes), not as a blanket verdict.
